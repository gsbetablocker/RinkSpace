# 实现状态

本页描述 `rebuild` 工作区中的可调用能力与已知缺口。算法与运行要求见 [SOLVER](SOLVER.md)，精确接口见 [INTERFACES](INTERFACES.md)，构建见[原生核心](../native/README.md)。研究结果按 [VALIDATION](VALIDATION.md) 判定；工程检查、优化器收敛和人工验收分别成立。

## 当前真实样本

[冈田芽衣短节目](../events/ankara_2026/programmes/okada_mei_sp/README.md)当前采用用户于 2026-11-02 指定的 `camera_solver_refined_1102` 暂定最终状态，覆盖 S01–S09 九镜头、三个物理机位，原片 22.120–188.680 秒、8329 个曝光。真实联合求解与完整回放均已执行；求解因代价进展停滞退出，未达到一阶数值收敛。S08 开头局部运动偏差、边界曝光的亚帧轨迹尖峰及独立物理标定限制仍保留。

当前实验采用七字段原始像素点，不含 W；共享场景、相机与 station 进入同一像素平方误差目标。精确点数、曝光、输入 SHA、场景和数值状态由节目入口及其[暂定最终结果绑定](../events/ankara_2026/programmes/okada_mei_sp/fit_v11/camera_solver_refined_1102.json)维护。

S01／S04 等轴焦距、六镜头 Lane 与历史九镜头 joint_mount_flex 基线各有对应快照的人工网格反馈，确认范围见节目入口。中间相机简化与冰面容差候选按各自状态解释；画面基本满意不表示机械／光学参数或运动轨迹已验证。冻结历史包见[离线审阅](GITHUB_REVIEW.md)。

## 原生几何与相机

可显式选择冰面容差场景：启用选项 64 后，选项合计为 127、布局为 layout146，增加 107 个相对共同名义量的有界偏差。图元与接线保持，原选项兼容。该版本已用于六镜头真实拟合及当前九镜头候选；数值状态与人工验收见节目入口。

`NativeSceneGPU` 编译显式选择的场景，只将本次输入引用的路径装入问题；完整场景库存仍由场景模型维护。冰面、围挡、固定连接点和广告共享同一 native 几何定义。未定位广告保留未定位状态，不能补造安装。

`project_motion` 通过隐式滚动快门方程求行曝光时刻，并在已认证根上微分。有限、在有效深度与光学域内且具有唯一曝光根的画外投影仍可参与求解。图像边缘不约束相机或 station，渲染时才裁切显示。时间有效域覆盖完整读出 halo。

相机基础局部 chart 每机位为 27 维；选择广角 Brown 扩展时为 31 维。方向列数由实际保留参数决定。连续运动使用独立镜头时间块，曝光 halo 通过端点三次多项式延拓；初值和每一方向使用一致基。时间平移不改变秒尺度，不跨切镜延拓同一运动。

静态与动态物理边界由调用者明确配置。连续样条的速度、加速度、jerk 使用各三次区间解析极值检查，覆盖帧间和曝光 halo；配置能力本身不表示某次运行采用了有依据的限值。

## 目标、约束与求解生命周期

当前原始点入口 `configure_pixel_linearization` 直接累计：

`0.5 * sum((u - u_obs)^2 + (v - v_obs)^2)`

它不读取统计 W、sigma 或 Huber 阈值；station 数值缩放只改变坐标，不改变像素残差。显式相关入口 `configure_linearization` 保留完整 W 和组级 Huber，用于相应合同及历史回归。原始图像查询使用 `configure_profiles(mode="exact")`，不能另设自由查询 station。

求解器在 native 内连续执行线性化、阻尼系统、可行步、真实目标评估和接受／拒绝。接受后重线性化，拒绝保留 accepted state。独立曲线点可调用全域或局部 station 细化；共享材料点身份不被拆开。可选 `profile_trial_stations` 仅适用于独立原始像素模式，在候选判定前完成对应搜索。

曲线端点、局部支持及相机／场景物理边界属于实际约束；图像矩形不属于可行域。约束投影、KKT／投影梯度、相对步长和真实代价共同决定数值停止。浮点停滞、缺乏代价进展、安全停止和数值收敛分别报告，不以拒绝步或阻尼增大冒充收敛。

进度回调返回 `False` 或 `request_stop()` 可安全停止，再次调用同一 handle 的 `solve()` 保留接受状态与阻尼继续。`export_state()` 导出 rig、运动控制点、station 和共享场景数值，但不包含跨进程恢复所需的全部优化器内部状态。

## 来源读取与输入准备

现有 prepare／review 接口检查显式模型、源身份、整数 PTS、路径关联与参数状态。原始字段及修订来源保留，输入准入不由模型投影自证。

来源读取模块可结合既有源库和视觉模块，从原片 RGB 读取边界、材料与拓扑并生成候选。配置 `enable_candidate_admission: true` 才允许候选进入相应准入流程，默认关闭；候选生成、原片回读、身份确认和完整节目验证是不同状态。已有局部真实检查和合成闭环不能证明全节目自动读取已交付。

## 人体局部拟合执行层

S01 既有全身、共享鞋体与开头分支已接入相同目标的紧凑 FK/LBS 优化、脚部采样缓存、局部导数 CPU 并行、同状态前向复用和共享鞋参的身体重放。独立 CPU 原生库新增完整运动相机的 XYZ 解析导数及可选 OpenMP，保持 ABI2；旧库继续走原导数入口。可选 CUDA 仅负责 FP64 紧凑人体前向，鞋体因子、相机、CSR 装配和 SciPy TRF/LSMR 仍在 CPU。

执行配置、启动包装和同状态评估命令见[环境说明](../environments/README.md#人体求解执行优化)。当前新动作／时序派生问题无需更改调用签名即可使用公共层；它们自己的附加物理残差求导仍沿用原实现。Data 中 body_perf_1103 记录本机数值与单次评估对照；未启动整轮性能对照拟合，也未实现 GPU 常驻身体 Jacobian／相机／线性求解，不能据此宣称整轮提速或人体位置与接触准确性已验收。

人体动作短段另有 `scripts/repair_action_root.py`：复用已保存的 GVHMR A/B 姿态与固定共享鞋刀，先修整段根平移，再在剩余预算内调姿态；两阶段共用同一身体、鞋刀和原生相机投影。`continuous_root` 对实际根加速度求残差，`continuous_pose` 保持已修根曲线。源阶段与条件初始化配置归节目 `root_trajectory_1103.json`，不产生新的支持观测，不固定旋转中心。预算监视可根据已测单次 Jacobian 耗时预留退出。2026-11-03 的三段实际结果减少了根往返漂移，但人体/鞋刀图像误差仍有退化且保留 SO(3) 跳变；它们是播放器中的未验收候选，不能视为人体定位或接冰已完成。


源支撑区域已通过 `support_image.py` 接入同一身体／鞋刀状态、五曝光节点native Brown及隐式行时间Jacobian；连续runner图像导数包含最低点沿rocker移动。`support_refinement.py` 可在局部C2窗联合开放root XYZ/SO(3)与明确支撑腿，`stage_quality.py`保留原A/seed/best/delivery分组对照；公共导出保留源标签，legacy硬冰面报告不参与当前软冰面交付门。2026-11-04真实88–92秒小窗做了两轮有界更新，图像训练区域局部改善，但review与世界runner轨迹仍失败，未扩完整事件。实际参数、预算与限制见[本轮索引](../events/ankara_2026/programmes/okada_mei_sp/spin_support_1104_audit.json)。
