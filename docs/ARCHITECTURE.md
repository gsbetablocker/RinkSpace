# RinkSpace 全项目重构：工程边界与迁移设计

审阅基准：`3e866a835dac26c461bb4ae436ae289814a1ae57`。本文是待实施的目标架构与明确改动清单；只有另附实际代码变更和运行结果所列部分已经实现。它替代上一轮把 G0 审核作为开工前置的流程。审计数据作为工程输入，不再要求用户先审核一遍诊断才开始重构。

## 1. 重构完成时，项目到底是什么

RinkSpace 是一套本地空间分析程序。输入为有准确原生 PTS 的比赛原片、已确认实体与已有观测，输出为共同场地、每镜头相机、同源审核叠加，以及带明确语义的运动员轨迹与分析。安卡拉是一个赛事数据实例，冈田芽衣短节目是一个节目实例；它们的名称和 S01 等镜头编号不得成为通用算法的分支条件。

生产程序只有一个 Python 包 `rinkspace`，一个通过 C ABI 调用的原生数学核心，一个 `rinkspace` 命令入口。目标原生核心包含 CPU 数值参考与 CUDA 求解实现，但两者共享几何、相机、残差定义，不是两套分别维护的数学模型。Ceres 只可用于小规模数值对照或历史回放验证，不能成为与新求解器并列的第二生产入口。

接手时使用的准确命令参数、当前已实现与目标接口状态、输入输出字段和错误行为见 [INTERFACES.md](INTERFACES.md)。本架构表中的服务名不代表同名命令已经实现；Codex 必须沿同一入口补齐接口，不能把尚未实现的调用包装成成功。

用户使用的流程为：**准备当前数据 → 运行选定镜头 → 看同一模型叠加 → 按用户反馈修正该阶段 → 用户通过后扩展镜头 → 获取轨迹与分析**。代码审核、依赖检查、格式转换等由 Codex 在内部完成；它们不是独立要求用户验收的阶段。

### 冈田芽衣短节目的完整范围

本次重构的节目目标是 **S01–S09 九镜头**。历史 `fit_joint6/scope.json` 只选了 S01–S06，并明确写有 `entire_programme_claimed: false`；它不是完整节目范围。新执行入口使用 [rebuild_scope.json](../events/ankara_2026/programmes/okada_mei_sp/rebuild_scope.json) 中的九镜头清单，不从某个六镜头运行目录推断节目范围。

现有顶层 `src/rinkspace/cli.py` 主要暴露 probe/index/sample/二维注册等命令；真实三维拟合的入口散在 `calibration/solve2/run_solver.py`、`run_original_ads.py`、`rinkfit_joint` 及 `solver_runtime` 中。`solver_runtime/runtime.py` 和 `event_factories.py` 还承担动态源加载。新架构必须收回这些运行入口，而不仅是再给旧入口加一层管理页面。

## 2. 目录、模块和依赖方向

目录表是最终边界，不要求第一天搬完所有文件。现有 `media.py`、`storage.py` 可原址保留并适配，避免大规模无收益改名。同名 `.py` 与包目录不得同时存在；例如引入 `review/` 时必须一次性重接原 `review.py` 的消费者。

| 路径 | 唯一职责 | 输入 → 输出 | 禁止承担的工作 |
|---|---|---|---|
| `src/rinkspace/cli.py` | 参数解析、选定项目与运行目标、调用应用服务 | 命令 → 服务调用与绝对产物路径 | 不写几何、不拼 Jacobian、不导入旧求解脚本 |
| `src/rinkspace/domain/` | 源时钟、实体、观测、场景、机位、镜头、轨迹与审核记录的数据合同 | 可序列化记录 → 有效领域对象 | 不依赖 OpenCV/CUDA，不访问历史源码 |
| `src/rinkspace/media.py` | 已有 FFmpeg/PyAV 原片索引与解码能力 | 原片/PTS → 原生曝光与可追溯图像 | 不识别场地身份、不决定几何 |
| `src/rinkspace/storage.py` | Project/Data 位置解析和原子文件操作 | 资产 ID → 已登记绝对路径 | 不自动搬运大数据、不把旧路径映射当成运行算法 |
| `src/rinkspace/observations/` | 原片测量、静止实体跟踪、有限实体关联、当前数据编译 | 原片+实体定义+旧观测 → PreparedDataset | 不因残差大自动改实体身份、不拟合相机来伪造观测 |
| `src/rinkspace/core/native.py` | 唯一的原生薄绑定、数组与 ABI 检查 | 领域对象/数组 → 原生句柄 | 不重写一套 Python 投影公式 |
| `src/rinkspace/session/` | 准备、启动、暂停、续算、检查点、运行状态和增量重建 | 当前数据+状态+任务 → 候选状态与运行产物 | 不重放历史资格链，不自动推进用户未通过的镜头 |
| `src/rinkspace/review/` | 同一核心投影、静帧放大、同 PTS 对照、镜头叠加编码 | 状态+原片 → 审核图/视频/结果索引 | 不另写投影、不隐藏难看的实体、不建立另一套项目管理系统 |
| `src/rinkspace/tracking/` | 身体参考点图像观测、三维/高度假设及世界垂直投影轨迹 | 已定相机+身体观测 → 明确语义的轨迹 | 不把像素射线落到冰面叫做人体质心垂直投影 |
| `src/rinkspace/analysis/` | 分段速度、距离、覆盖与不确定度传播 | 有单位及来源的轨迹 → 分析与导出 | 不把条件米制标成测量真值，不跨缺失段补造运动 |
| `src/rinkspace/compat/` | 一次性读取旧状态/观测，产生当前格式及映射 | 旧静态文件 → 新当前格式 | 不被正常 solve/resume 运行导入，不修改旧原件 |
| `native/include/rinkspace/` | 同源几何、相机、残差、参数布局与引擎接口 | 纯数值参数 → 结构化数值结果 | 不读取 JSON、不识别赛事名、不打开原片 |
| `native/src/` | C++ 引擎、局部变量处理、LM、CPU 参考、原生 API | 已编译问题 → 迭代与状态 | 不启动其他历史求解器 |
| `native/gpu/` | CUDA 前向/导数、权重、块累计、消元及线性后端 | 常驻 GPU 数组 → 目标/块系统/增量 | 不每轮把全量 Jacobian 下载回 Python |
| `native/include/rinkspace/core_api.h` 与 `native/src/core_api.cpp` | 唯一 C ABI、生命周期与错误传播 | 数组/句柄 ↔ 原生核心 | 不再另建 bindings 框架，不保存领域状态的第二份真相 |
| `events/<event>/` | 当前赛事场地、实体、事实、广告、安装时期与最终模型 | 核实事实与候选/已通过状态 | 不放公共算法或逐帧大数组 |
| `tests/` | 关键数学反例、兼容与真实回归入口 | 小型可复现证据 → 工程缺陷定位 | 不用通过数量冒充画面进步 |

依赖方向固定：`CLI → session / review / tracking → domain + core + media/storage`；`observations → domain + media + core`。`domain` 不回调上层，`native` 不反向依赖 Python。渲染和残差调用同一核心的 `project`，不允许两个“相似实现”。

### 原生文件划分

| 实现文件 | 内容 |
|---|---|
| `native/include/rinkspace/core_types.hpp` | 向量、坐标域、状态码、数组视图、ID、标量模板 |
| `native/include/rinkspace/geometry.hpp` | 连续围挡、共享印刷族、有限曲线、已确认交点、广告展开映射 |
| `native/include/rinkspace/projection.hpp` | 相机光心、旋转、变焦与畸变、投影约定；CPU/CUDA 共用 |
| `native/include/rinkspace/problem.hpp` | 参数块、因子关联、来源组、活跃参数集合、稀疏布局与 `compile_problem` 边界 |
| `native/include/rinkspace/solver.hpp` | `solve` 公共数值边界；`step` 属于内部迭代，`snapshot/request_stop` 是生命周期辅助，精确合同见 `INTERFACES.md` |
| `native/src/core_api.cpp` | 基础几何与投影 API，本轮首切片落点 |
| `native/src/problem.cpp` | 领域数据到数值索引、共享参数所有权与规约 |
| `native/src/solver.cpp` | 单一求解循环；与 GPU 后端无关的状态管理 |
| `native/gpu/evaluate.cu` | 同一前向模型的批量残差与局部导数 |
| `native/gpu/reduce.cu` | 相关组权重、块稀疏累计 |
| `native/gpu/local_eliminate.cu` | 相关局部变量连通组消元与回代 |
| `native/src/cudss_system.cpp` | 稀疏分析、分解、求解与内存状态 |
| `native/src/checkpoint.cpp` | 数值状态与续算内容的原子保存 |
| `native/CMakeLists.txt` | 唯一原生构建；构建产物进入 Data build 目录 |

首切片中 `rs_curling_*` 接受行数参数；安卡拉事件传入 4 行，算法不写死 4 行。`compat/d78_geometry.py` 只从真实 d78 提取未拟合结构 seed，不能替代后续 `d78_state.py` 的完整状态忠实回放。

本轮首切片只实现已经有实际源码与运行结果支持的文件。表中其余文件是后续改动目标，禁止创建空函数并把它们标为“架构已接通”。

公共数值调用以 `compile_problem → solve` 与同一核心的 `project` 为边界；准备数据属于上层服务，迭代步骤不成为另一个生产求解入口。

## 3. 统一的数据模型

### 3.1 六种长期领域对象

| 对象 | 必须保存的字段 | 生命周期 |
|---|---|---|
| `Source` | `source_id`, SHA, 宽高, `time_base_num/den`, 原生 PTS 索引, 外部原片资产 ID | 原片登记后不随优化变化 |
| `Scene` | `scene_id/revision`, 坐标系与尺度声明, 参数族, 几何实体, 围挡表面, 广告安装, 有来源的事实 | 同一场地/布置时期共享；候选更新不覆盖用户通过版 |
| `Rig` | `rig_id`, 安装时期, 安装支点及杆臂模型, 光学模型种类, 已知与待估的参数 | 物理机位共享；安装移动产生新时期 |
| `Shot` | `shot_id`, `source_id`, PTS 范围, `rig_id`, 运动样条与变焦状态 | 镜头特有；切镜不做时间平滑连接 |
| `Observation` | 原始像素、PTS、实体关联、测量含义、相关组、协方差或其引用、跟踪质量、来源与人工决定 | 原始测量不可变；关联更正显式新增修订 |
| `Trajectory` | 身体参考定义、图像观测、位置含义、假设/单位、缺失与腾空状态、scene/camera revision | 依赖对应相机；上游改动后标明适用性 |

`Scene` 不含每帧相机；`Shot` 不复制场地；`Observation` 不存一份随优化改动的“真值 XYZ”；交点通过共享实体关系求世界位置。

### 3.2 固定点与普通曲线测量不能共用模糊的 station 字段

- `FixedJunction(parent_a, parent_b, branch, meaning)`：两条已知实体的确定分支交点，没有逐帧站位；若全局场地参数变化，其世界位置由同一场地推导。
- `MaterialPoint(surface_id, coordinates)`：围挡/广告上的固定实体点，绑定已确认的材料参数坐标。
- `CurveSample(feature_id, finite_support)`：有限曲线上普通样本，可有局部对应；它不能冒充固定角点。
- `CandidateAssociation(candidates, evidence)`：身份有疑义，尚未成为固定对应；保留给自动消歧和少量用户疑义簇审核。

数学交点即使存在，也不自动等于已经在原片中测到。反过来，旧格式中已有确认的像素与身份也不因“legacy”标签而失效。

### 3.3 明确修正上一版合同中的两个错误门槛

**旧来源不等于不可信。** 已经确认的旧 UV、原生 PTS、实体语义与相关组，经过等价格式转换后可以直接激活，不要求用户重新逐帧确认。导入保留旧记录 ID 与映射，转换器不重新估计观测。

**自动观测不要求逐条人工通过。** 若实体身份已确认、像素来自正确源域、跟踪/遮挡/局部质量检查通过，可以进入活动观测。用户审核的是疑义簇与完整视觉结果。身份未知、明确拒绝或仅数学合成的交点不能进入真实观测集。审核来源与测量质量分开存，不能用一个 `human_reviewed=false` 让全部自动数据失效。

### 3.4 PreparedDataset 是运行输入，不是历史流程回放器

逻辑内容固定为：

1. `manifest.json`：格式版本、源/场景/镜头引用、数组描述、实体表、相关组表、必要生成配置。
2. 连续 `.npy` 数组：源索引、整数 PTS、shot/feature 索引、原始 UV、观测类型、相关组、活动掩码、不确定度表示与有限支撑。
3. `features.json`：稳定的实体定义及固定点父实体/分支。

数组可 mmap；求解器接入时按已编译索引搬到 GPU。原始 UV 保留双精度，GPU 工作精度由经验证的路径决定。时间以整数 PTS 存储，计算时先减去本镜头时间原点再转浮点秒。

相关源测量组成的权重块必须保留，不能只留下每行独立 sigma。重叠来源去重依据同一原始证据组；在一帧增加交点不会删除这一帧所有其他观测。

准备只在观测、关联、几何实体/拓扑或对应依赖变化时重编译受影响部分。正常 solve/resume 只检查当前格式、索引、数组形状和输入状态引用，不重读全部历史包、不重跑原片测量、不重新遍历旧源码。

## 4. 当前状态、候选与用户通过版

每个运行有一个 `RunState`，包含：当前数值状态、当前目标分项、活动参数集合、输入 revision、求解器续算信息、最后完整检查点。`candidate` 和 `user_approved` 是两个独立概念；数值接受步不会改用户通过指针。

`Checkpoint` 保存参数、局部变量必要状态、LM 状态、参数布局/尺度、因子/输入引用，以及可重建 GPU 缓存的版本信息。稀疏分析缓存可丢弃重建；不需要重新生成原始观测。发现数据依赖变化时明确列出需重建范围，不把整个历史重新跑一遍。

停止信号在原生迭代的安全点处理，先保存最近一个完整状态；不把半写文件当作续算点。运行目录创建后立即打印主日志绝对路径，之后才启动耗时准备和求解。日志保存阶段、耗时、内存、实际参与的各类观测数量、目标分项和接受/拒绝原因；用户消息只报告实际进展与阻塞，不报告无意义测试数。

### 数据存储位置

| 位置 | 保存内容 |
|---|---|
| OneDrive 项目 `src/`, `native/`, `environments/` | 公共源码、可复用构建环境定义 |
| OneDrive `events/<event>/` | 小型用户事实、实体/机位定义、当前最终参数、节目绑定、精确资产引用 |
| Data `sources/` | 原片和 PTS 索引；已登记旧路径优先复用 |
| Data `prepared/<dataset_id>/` | 当前观测列数组及索引；不能依赖历史运行目录 |
| Data `runs/<run_id>/` | 检查点、日志、每镜头审核产物、性能轨迹 |
| Data `build/` 与 `cache/` | 原生编译、视觉模型缓存、大型中间数组 |

表中的目录为逻辑归属，实施先复用现有资产位置，不为了整齐搬几十 GB。路径解析统一通过 `storage.py`，旧地址在静态映射里保留。修改 OneDrive 项目路径后执行已有 `scripts/check_onedrive_paths.py`。不改 Git 数据库位置，不自动提交或推送。

## 5. 统一入口与最小审核界面

### 目标命令面

下表为待实现的最终命令接口；当前实际可用命令由本轮代码和 `--help` 输出定义，不将未来接口当成已实现。

| 命令族 | 行为 |
|---|---|
| `rinkspace source` | 登记、定位、索引原生曝光，沿用已有 media/storage 能力 |
| `rinkspace model import-d78` / `rinkspace model preview` | 本轮首切片的实际命令；分别导入未拟合结构 seed、生成核心几何预览。未来完整状态导入继续留在 `model` 命令族，不另开相冲突的顶层入口 |
| `rinkspace prepare` | 把选定事件/镜头的当前数据编译为自包含 PreparedDataset |
| `rinkspace solve` | 用已准备数据和显式初值运行统一引擎；单镜头/多镜头仅由选择数据决定 |
| `rinkspace resume` | 从完整检查点续算同一问题；不触发历史生成链 |
| `rinkspace review` | 输出同模型、同 PTS 的全实体审核画面和局部放大 |
| `rinkspace track` | 在已适用的相机结果上生成身体参考点轨迹 |
| `rinkspace analyze` | 按声明单位和缺失段生成距离、速度、覆盖等结果 |

现有顶层 CLI 保留，按需懒加载这些命令。旧命令不能悄悄改含义；二维 `fit-map` 与条件平面映射继续明确标为二维工具。

### 审核界面只回答三个问题

1. 当前这段原片，网格、围挡和广告是否贴合？
2. 与最近用户通过版相比，哪里变好、哪里变差？
3. 本轮具体改了哪些输入或模型参数，下一次修正针对哪里？

为此只生成一个短索引、关键帧放大图、需要审核的完整镜头视频，以及机器可读 `review.json`。视频给绝对本地路径和源时间供 PotPlayer 播放，不在聊天或内置播放器嵌入。未经明确改善不重复编码完整节目。

侧边日志、任务看板、历史文档墙和另一套项目控制台都不是这次重构的必要组成。已有 UI 中可用的帧定位与点选代码保留；其几何投影必须改为从同一原生核心取得，浏览器只画已经返回的路径。

## 6. 旧代码的去向

完整机器可读映射见 `MIGRATION.json`。迁移准则是“能力进入新边界，历史证据留下，旧生产路径退出”；不是把旧目录整体改名成 legacy 后继续动态 import。

| 现有对象 | 处理 | 退出条件 |
|---|---|---|
| `media.py`, `storage.py`, `path_policy.py`, `resource_registry.py` | 保留并适配领域 ID，削减重叠包装 | 当前业务服务统一调用后，再合并重复辅助函数 |
| `workspace.py`, `camera_timeline.py`, `camera_classification.py` | 提取源准备、分镜和机位分类能力到明确服务，保留已确认机位数据 | 新 Source/Shot/Rig 可以消费相同已有登记 |
| `calibration/solve2/rinksolve/schema.py` | 复用有用的类型语义，精简为 `domain`；不复制两千行通用表达式系统 | 所有活动新输入只使用统一合同 |
| `model.py`, `projector.py`, `project_at.cu`, `board_at.cu` | 迁移已核实公式到同源 native 几何/投影，纠正已确认共享关系 | 旧基线回放等价与新真实镜头审核分别完成 |
| `parameterization.py`, `optimizer.py`, `constrained.py`, 原广告独立求解器 | 由统一 Problem/Solver 替换；广告成为同一场景因子类型 | S01 新路径已达到视觉基线且性能记录真实 |
| `preparation.py`, `observations.py`, `sources.py` | 改为一般化 prepared 编译；旧 source 文件只由 compat 读取 | 直接消费当前数据，不需要历史模块 |
| `vision_*`, `landmark_*`, `scene_observations.py` | 按测量/关联/质量/跟踪四类合并；可用检测器以函数方式复用 | 输出统一 Observation，赛事特例移到数据 |
| `calibration/solver_runtime/` 与 `calibration/rinkfit/` 生产入口 | 冻结为历史复现工具；新运行时不依赖动态加载与恢复链 | 导入覆盖所需历史格式，新生产路径拥有完整结果 |
| `calibration_companion/` 中相机/几何/旧求解 | 公式经过对照后进入 native；旧 pickle/状态需要的格式读取留在 compat | 没有新领域对象回调旧 Python 几何 |
| 各种 renderer/server/workbench | 保留解码、图像合成和已有点选能力；投影改走核心 | 审核与求解读取同一参数 snapshot |
| `athlete_continuity.py`, `motion.py`, `metric_scale.py` | 保留可用分段和统计，重接明确语义的轨迹 | 不再以接触点或平面射线落点冒充身体垂直投影 |
| `events/` 人工事实、原始观测和失败记录 | 保留原件和身份；增加当前格式引用，不批量清理 | 永不以“旧格式”为理由丢失不可重建证据 |

删除旧源文件是迁移后的清理动作，不是第一批动作。每个退出项都要有当前消费者清单；静态 import 检查和实际加载路径需同时核实，尤其是 pickle 和动态 import。正常求解从一开始就不能新增对旧恢复链的依赖。

## 7. 五批实际改代码的任务

每批下面的内部步骤均由 Codex 连续完成，不逐个要求用户审批。用户只在可见结果出现时审核。发现该批范围内错误，应修正到该批交付成立；跨阶段改变物理假设时明确说明，不能通过改标签掩盖。

### A：把场地、相机与数据收进唯一核心

**修改文件：** `domain/contracts.py`、`core/native.py`、native 基础几何/投影文件、`compat/d78_geometry.py`（首切片结构 seed）与 `compat/d78_state.py`（待实现完整状态）、顶层 CLI 的对应 dispatch、赛事当前实体定义。

内部工作：实现统一领域对象；共享几何通过构造成立；导入旧确认观测且保留 UV/PTS/语义；区分旧冻结回放几何与新结构化候选；用统一核心生成模型俯视图和原片叠加；核对完整 d78 S01 回放是否忠实。

**用户可见交付：** 新共同场地的俯视图与标注节点；d78 原状态完整 S01 的同 PTS 回放；若某项不支持，明确缺失实体，不能隐藏。新结构化几何尚未重新拟合时不冒充已贴合。

**停止位置：** 用户看到了新项目核心实际生成的几何和真实片段，确认身份与回放无退化后进入 B。当前云端首代码切片只完成 A 中基础几何/投影/合同部分；这部分运行成功不等于 A 的原片验收已经完成。

### B：统一 GPU 引擎完成整个 S01

**修改文件：** `problem.hpp/.cpp`、`solver.hpp/.cpp`、GPU evaluate/reduce/local_eliminate 和 cuDSS 后端、`observations/{extract,associate,compile}.py`、`session/{prepare,solve,resume}.py` 与 `native/src/checkpoint.cpp`、`review/{render,compare}.py`。

内部工作：从本机已有观测开始；补充自动提取的可靠固定点与跟踪；锁定实体身份；落实完整目标和全局/局部参数布局；完成 GPU 常驻循环；逐项验证初始化、镜头运动与光学项；真实计时定位瓶颈。广告在同一个问题里，不再另起一个广告求解架构。

**用户可见交付：** 完整 S01 1248 帧，同 PTS 显示所有已建模实体；近景广告与易抖处的放大；相对 d78 的变化；真实运行时与显存。接受标准是用户视觉判断，性能目标由实测建立，不沿用未经测量的 2 秒/5 秒承诺。

**失败时范围：** 修相应几何/相机/观测/目标或 GPU 实现；不得改掉原始像素语义、删除难看的实体、隐藏广告或增加逐帧自由形变绕过问题。

### C：同一引擎逐镜头完成 S01–S09

**修改文件：** `session/selection.py`、一般化 problem assembler、Rig/Shot 参数共享与时间支撑；相应赛事/节目选择数据。

内部工作：S01 通过后先加入 S04，再加入 S02、S03、S05、S06、S07、S08、S09；每次选择使用同一九镜头节目清单，并只增加相应 Shot 的活动状态与因子。S01–S06 可以作为过程中的验证子集，不能成为完成条件；S07–S09 也不能留成未定义的“以后剩余镜头”。选择不同镜头不得创建新求解类。实际安装/光学共享关系由已有 Rig 绑定和 epoch 记录，不能依据画面相似就强制相同；现有绑定不等于旧失败模型的物理参数已通过。

**用户可见交付：** 每次增加一个镜头，给该镜头完整叠加和之前已通过片段的直接对照；用户不通过就修这个增量，不继续加镜头。这里的多次停点是用户要求的逐镜头视觉验收，不是审核内部编译步骤。

**完成条件：** 同一共享场地解释九镜头，全部 S01–S09 均有完整采用区间的视觉验收，已通过镜头不退化；九镜头可以一次启动、暂停与续算，没有临时脚本或历史准备依赖。全节目检查核对九个镜头 ID、8434 个原生 PTS、八个切镜边界及 S09 的用户截止范围，不能仅检查最终选择的镜头数量。

### D：九镜头连续输出与可复用赛事接入

**修改文件：** 一般化 source/shot selection、review、epoch 模型、事件导入与最终模型导出。

内部工作：在 C 已完成九镜头的基础上，生成同一场地状态下的完整采用区间输出，复核切镜处的坐标一致性、恢复运行和最终导出；不在这一批才补入被遗忘的 S07–S09。广角属于独立实际机位，按存在的素材和工作范围接入，不为本节目九镜头清单之外的机位增加强制步骤。用另一赛事的数据实例检验公共接口；没有第二赛事证据时，只能声明接口一般化，不能宣布跨赛事效果已验证。

**用户可见交付：** S01–S09 全部 8434 帧的连续叠加；八个切镜边界、画面边界和近景各有明确对照；可复用的事件配置与资源路径。节目之外的广角或第二赛事结果只有实际纳入并处理后才能列为完成。

### E：身体主轨迹、统计与展示

**修改文件：** `tracking/{reference,observe,reconstruct}.py`、`analysis/{segments,kinematics,coverage}.py`、review 的轨迹图层。

内部工作：保留一致的身体参考定义，明确从像素到三维点/高度假设再到垂直投影的链路；身体参考点不是触冰点，腾空段不能补成接触。单目深度不可观测处保留条件与不确定度。场地坐标未有验证的米制标定时，输出归一化/条件单位，不能把假定 60 m 写成真实测量。

**用户可见交付：** 同一场地参照下的单条身体主轨迹、旋转段表现、跳跃与遮挡段状态，以及有单位依据的距离/速度/覆盖。人体连续性首先作为相机/场地结果的诊断；不能把人物错误地作为静态场地实体加入标定观测。

## 8. 第一批如何直接接手

本轮第一代码切片位于隔离的 `rinkspace-rebuild` 工作树。代码按上面稳定目录落地；没有提交或推送。接手 Codex 应先看实际 diff 与运行产物，然后继续完成 A 批剩余部分。不要再要求用户批准 G0，不重做一遍历史审计；源码比本基准更新时，只对受影响接口进行合并。

实现任务的准绳是：**通用领域模型确定归属，同一数学核心保证投影一致，自包含数据保证可运行，单一引擎保证扩镜头不换架构，用户看到的真实完整片段决定是否推进。**
